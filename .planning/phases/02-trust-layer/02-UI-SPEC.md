## Spacing Scale

Inherited from Phase 1 without changes.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline label-to-value gaps within breakdown lines |
| sm | 8px | Gap between label and input within a field row; gap between sublabel and its parent label |
| md | 16px | Default spacing between input fields; padding inside input boxes |
| lg | 24px | Spacing between the input section and the breakdown section |

| 2xl | 48px | Vertical padding above and below the calculator card |

## Typography

Inherited from Phase 1. One new role activated this phase: **Body**, which was reserved in Phase 1 for Phase 2 trust copy.

| Role | Size | Weight | Line Height | Phase 2 Use |
|------|------|--------|-------------|-------------|
| Body | 16px | 400 (regular) | 1.5 | Tax guidance text (TRUST-01); limits callout (TRUST-03) |
| Label | 14px | 400 (regular) | 1.5 | All input labels; breakdown line labels (unchanged) |
| Sublabel | 14px | 400 (regular) | 1.4 | Breakdown line sublabels (TRUST-02) — new this phase |
| Heading | 20px | 600 (semibold) | 1.2 | Calculator section title (unchanged) |

**Sublabel** shares the 14px size with Label. Hierarchy is signaled by color alone: Label uses `#3F3F46` (zinc-700), Sublabel uses `#A1A1AA` (zinc-400). Source: 02-CONTEXT.md Claude's Discretion.

Two weights in use across the system: 400 (regular) and 600 (semibold). No additional weights introduced.

## Component Inventory

### Modified: BreakdownRow

Existing component at `src/components/Calculator.tsx:135`.

Add optional `sublabel?: string` prop. When provided, render the sublabel as a second line directly below the label, within the same left-aligned column. When not provided, render identically to Phase 1 — no layout shift on rows without sublabels.

```
[label text — 14px, zinc-700]
[sublabel text — 14px, zinc-400]    ← rendered only when sublabel prop is provided
                    [value — 14px, zinc-700 or zinc-400]
```

Sublabel sits 4px below the label (xs gap). The value column remains right-aligned, vertically centered to the label row.

Call sites:

| Row | sublabel prop |
|-----|---------------|
| `<BreakdownRow label="Balance" ...>` | not passed — no sublabel |
| `<BreakdownRow label="Tax reserve" ... sublabel="Set aside in case your tax bill hits">` | static string |
| `<BreakdownRow label="Runway buffer" ... sublabel={\`Covers ${runwayMonths} months if work goes quiet\`}>` | dynamic — reflects live `runwayMonths` input value |
| `<BreakdownRow label="Safe to spend" ...>` | not passed — no sublabel |

Source: 02-CONTEXT.md D-01 through D-04.

### New: Tax Guidance Text (TRUST-01)

Element: `<p>` directly below the tax rate `<input type="range">` element in the JSX.

- Size: Body (16px, weight 400, line-height 1.5)
- Color: `#3F3F46` (zinc-700)
- Always visible — not conditional on slider position
- Copy: `"Typical Dutch ZZP'ers: 25–35% after deductions"`
- Margin-top: 4px (xs) below the slider element

Source: 02-CONTEXT.md D-05, D-06, D-07.

### New: Limits Callout (TRUST-03)

Element: `<p>` placed after the full breakdown section, before the closing tag of the calculator card.

- Size: Body (16px, weight 400, line-height 1.5)
- Color: `#3F3F46` (zinc-700)
- No border, no background box, no icon — plain paragraph
- Always visible
- Copy: `"This doesn't account for upcoming large expenses or invoices not yet in your balance."`
- Margin-top: 16px (md) above the callout, separating it from the breakdown

Rationale: calm, factual tone consistent with Phase 1 over-reserved message (D-08, D-12). No alarm styling. Source: 02-CONTEXT.md D-11, D-12.

## Interaction Contract

Inherited from Phase 1. One addition:

| Trigger | Response |
|---------|----------|
| User types in Balance or Monthly Expenses | Breakdown and sublabels update immediately on every keystroke |
| User moves Tax Rate slider | Breakdown and % display update on every `input` event |
| User changes Runway Months | Breakdown updates; runway buffer sublabel updates to reflect new value (e.g. "Covers 4 months if work goes quiet") |
| Any input is empty or zero | Affected breakdown lines show `—`; sublabels remain visible even when value shows `—` |
| All 4 inputs have valid values | All breakdown lines show computed values with sublabels |
| `taxReserve + runwayBuffer >= balance` | Safe to Spend shows `$0`; over-reserved message appears; limits callout still visible below |

Sublabels are always visible — not toggled, not on hover. Source: 02-CONTEXT.md D-01.
